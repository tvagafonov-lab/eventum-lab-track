# ПУЛЬТ · спецификация манифеста (v1)

Манифест `pult/product.yaml` — единственный источник правды о структуре продукта.
Панель `pult/panel.html` — производная от него (генерируется, руками не правится).
Этот документ — контракт формата: и для человека, и для агента.

## Корень

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `pult` | int | да | Версия схемы манифеста. Сейчас `1`. |
| `product` | object | да | Паспорт продукта. |
| `modules` | list | да | Модули (конвейерные и служебные). |
| `flows` | list | да | Связи конвейера (может быть пустым на этапе спецификации). |
| `uses` | list | нет | Связи «модуль → служебный модуль». |
| `shared` | list | нет | Общие файлы, принадлежащие нескольким модулям. |

## `product`

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Человеческое имя продукта. |
| `codename` | slug | Латинский идентификатор (для файлов, веток, артефактов). |
| `tagline` | string | Одно предложение: что делает продукт. |
| `status` | enum | `spec` (только спецификация) · `build` (в разработке) · `live` (работает) · `frozen` (заморожен). |
| `owner` | string | Владелец продукта. |
| `updated` | date | Дата последнего обновления карты. Агент обновляет при каждом sync. |
| `updated_by` | string | Кто обновил: `agent` или имя человека. |
| `docs.product` | path | Путь к файлу-описанию программы (PRODUCT.md). Обязательное чтение агента. |
| `docs.changelog` | path | Путь к changelog. Обязательное чтение и обязательная запись агента. |
| `repos` | list | Репозитории продукта: `{id, url?, note?, verified}`. Для однорепозиторных продуктов — один элемент. |

## `modules[]`

| Поле | Тип | Описание |
|---|---|---|
| `id` | slug | Уникальный идентификатор модуля (латиница, kebab-case). На него ссылаются `flows`, `uses`, `shared.used_by`. |
| `title` | string | Имя модуля на панели. |
| `icon` | emoji | Один эмодзи — иконка блока. |
| `kind` | enum | `pipeline` — участвует в конвейере · `service` — служебный (Telegram, планировщик, БД…): выпадает из основного потока и рисуется в отдельной нижней полосе. |
| `status` | enum | `spec` — описан, кода нет · `build` — в разработке · `ready` — работает · `debug` — в отладке · `off` — отключён. |
| `verified` | bool | `true` — владелец подтвердил, что модуль описан верно. `false` — гипотеза агента (панель помечает знаком «?»). Агент НИКОГДА не ставит `true` сам — только человек или по его явному слову. |
| `summary` | string | Одна строка: что делает модуль. Видна в свойствах. |
| `details` | text | Развёрнутое описание: зачем, крайние случаи, ограничения. |
| `files` | list | Рабочие файлы модуля, см. ниже. |
| `variables` | list | Переменные модуля, см. ниже. |
| `position` | {x,y} | Необязательно. Ручная позиция на канве; если нет — панель раскладывает автоматически. |

### `modules[].files[]`

`{ repo, path, role, verified }`

- `repo` — id репозитория из `product.repos` (для однорепозиторных можно опустить).
- `role`: `owner` — файл целиком принадлежит модулю · `part` — модуль занимает часть файла · `reads` — модуль только читает файл.
- Путь может указывать на каталог (`src/radar/`) — весь каталог принадлежит модулю.

### `modules[].variables[]`

| Поле | Описание |
|---|---|
| `key` | Имя переменной (как в коде/конфиге). |
| `title` | Человеческое название. |
| `type` | `number` · `string` · `bool` · `enum` (+ поле `enum: [..]` со списком значений). |
| `value` | Текущее значение (снимок на момент sync). |
| `edit` | `panel` — можно менять из панели (попадает в черновик изменений) · `code` — только через кодинг (панель показывает замок и `location`). |
| `location` | Где переменная живёт: `repo:путь` (+ якорь при желании). |
| `hint` | Подсказка: что значит переменная и чем грозит изменение. |
| `verified` | Как у модуля. |

Секреты (токены, ключи) в манифест не попадают никогда: только `value: "•••"`,
`edit: code` и location до `.env`/секрет-хранилища.

## `flows[]`

`{ from, to, label?, when?, verified? }`

Направленная связь конвейера между `pipeline`-модулями.
- `label` — что передаётся по стрелке (данные, событие).
- `when` — условие срабатывания; ребро рисуется пунктиром с подписью условия. Так выражается условное выполнение (ветвление = несколько `flows` из одного модуля с разными `when`).

## `uses[]`

`{ module, service, note? }`

Связь «конвейерный модуль пользуется служебным». Рисуется тонким пунктиром к нижней полосе. Не участвует в раскладке конвейера.

## `shared[]`

`{ repo, path, note, used_by: [id...], verified }`

Файлы, общие для нескольких модулей (схемы данных, конфиг, логгер).
Панель показывает их отдельным блоком «Общие файлы»; при выборе модуля — его общие файлы видны во вкладке «Файлы».

## Инварианты (проверяются в режиме doctor)

1. Все `id` модулей уникальны; все ссылки (`flows`, `uses`, `shared.used_by`) указывают на существующие id.
2. `flows` соединяют только `pipeline`-модули; `uses.service` указывает только на `service`-модули.
3. Каждый файл с `verified: true` существует в репозитории по указанному пути.
4. Файлы репозитория, не входящие ни в один модуль и ни в `shared`, — кандидаты в «сироты» (doctor их перечисляет, но ничего не делает сам).
5. Секретов в манифесте нет (значения токенов/ключей/паролей не сохраняются).
6. `panel.html` сгенерирован из текущего `product.yaml` (данные не разошлись).
