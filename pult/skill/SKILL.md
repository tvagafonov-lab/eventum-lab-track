# pult — карта продукта и панель управления

Оболочка визуального отображения продукта: манифест `pult/product.yaml`
(источник правды), панель `pult/panel.html` (генерируется), PRODUCT.md
и CHANGELOG.md (обязательное чтение). Формат карты — `pult/SCHEMA.md`.

## Железные правила

1. **Перед работой над продуктом** прочитай PRODUCT.md, CHANGELOG.md
   и pult/product.yaml. Человек мог изменить свойства или переменные —
   карта новее твоей памяти о проекте.
2. **После значимого изменения кода** — безусловно, не дожидаясь просьбы:
   обнови карту, добавь запись в CHANGELOG.md, перегенерируй панель
   (см. render). Всё это — в том же коммите, что и изменение кода.
   Значимое изменение = изменилось поведение, файлы, переменные, статус
   или связи хотя бы одного модуля.
3. **`verified: true` ставит только человек.** Ты ставишь `verified: false`
   на всё, что реконструировал, спроектировал или предположил.
   Снимаешь «?» только по явному слову владельца («подтверждаю», «верно»).
4. **panel.html руками не правится.** Любое изменение данных — через
   product.yaml + render. Правка шаблона панели — отдельная осознанная
   задача, не побочный эффект.
5. **Секреты в карту не попадают.** Токены, ключи, пароли — только
   `value: "•••"`, `edit: code` и location.
6. **Связи из панели не настраиваются.** Черновик изменений из панели
   касается только переменных с `edit: panel`. Просьбу «перепаяй связи»
   выполняй в коде и карте, а не выдумывай механику панели.

## Режимы

### init — завести Пульт для продукта (этап спецификации)

1. Скопируй в репозиторий продукта: `pult/SCHEMA.md`, `pult/tools/embed.py`,
   шаблон панели `pult/panel.html`, шаблоны `PRODUCT.md` и `CHANGELOG.md`
   из `skill/templates/`.
2. Вместе с владельцем (или по ТЗ) собери карту-костяк: модули со статусом
   `spec`, связи, будущие переменные. Всё — `verified: false`.
3. Добавь в CLAUDE.md продукта вставку из `skill/templates/CLAUDE-snippet.md`.
4. Сгенерируй панель (render), покажи владельцу, спроси, что понято неверно.

### sync — обновить карту после изменений кода

1. Определи затронутые модули (по файлам диффа и маппингу `files`).
2. Обнови: статусы, файлы (роли owner/part/reads), переменные и их текущие
   значения, связи, `product.updated`, `product.updated_by: agent`.
3. Новый функционал вне существующих модулей = новый модуль
   (`verified: false`). Служебное (мессенджеры, планировщик, БД, внешние
   API) — `kind: service` + связи `uses`.
4. Файл, нужный нескольким модулям, — в `shared`, не дублируй в `files`.
5. Запись в CHANGELOG.md: дата, что изменилось, какие модули затронуты.
6. render.

### render — перегенерировать панель

```bash
python3 pult/tools/embed.py        # product.yaml → JSON → pult/panel.html
```
Скрипт заменяет данные между маркерами `PULT:DATA:START/END`. После —
открой/опубликуй панель, если человек просил посмотреть.

### doctor — сверить карту с реальностью

Проверь и доложи (сам ничего не чини без слова владельца):
1. Ссылочная целостность карты (см. инварианты в SCHEMA.md).
2. Каждый файл с `verified: true` существует по указанному пути.
3. Файлы-сироты: есть в репо, но не принадлежат ни одному модулю и ни shared.
4. Переменные: значение в карте совпадает со значением в `location`.
5. Данные в panel.html совпадают с product.yaml (перегенерируй при дрейфе).

### verify — принять подтверждение человека

По слову владельца («радар описан верно», «подтверждаю всё, кроме X»)
проставь `verified: true` адресно, обнови панель. Массовое подтверждение —
только по явной массовой формулировке.

## Применение черновика изменений из панели

Человек приносит текст «Задание для агента» из панели. Для каждой строки:
1. Найди переменную в карте, проверь `edit: panel` (иначе объясни, почему
   менять надо кодом).
2. Измени значение в настоящем доме переменной (`location`), затем в карте.
3. CHANGELOG.md + render. Ответь короткой сводкой применённого.
